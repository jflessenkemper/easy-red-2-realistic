## What "proven" means here

**proven** = the behaviour was measured in a running game (log/telemetry analysis, cited in the
README row). **partial** = some halves measured in game, others not. **unproven** = no in-game
evidence at all (offline tests do not count). Nothing in this pack promotes a status:
`tools/build_evidence.py` refuses any status above `baseline_status` unless the feature has BOTH a
30 fps clip file AND an `eval_telemetry.py` JSON with that feature PASSING (check 12 tests the gate).
No row currently has a 30 fps clip, so even "proven" rows are log-proven, not video-proven.

## Findings from the new tools (none required a behaviour change)

1. **`LUA_PATH` from luarocks breaks `luajit -bl`** (hides `jit.*`), which would silently turn
   checks 2/4d into failures/skips. Fixed in `tests/env.sh` (re-appends `;;`).
2. `RealisticEvents.lua` declares `local function addVeh` **twice** (lines 542 and 1130) with
   different signatures. Not a bug today (each caller is after its own definition), but it spends a
   main-chunk slot in the file with 3 spare. Recommend renaming the second on a branch.
3. Six top-level scenario rigs in the phase script are unused in the shipping build (`T10`,
   `T9_T6`, `T9_T6_VEHICLES`, `T9_T6_MOUNTED`, `FORMRIG`, `BRAIN`) — 6 slots. Grouping them into one
   table would raise headroom 3 → 8. Not done: touches deploy variant mechanics.
4. `Realistic.lua` `dragTarget` is written but never read (dead state; 17 still works off other state).
5. `bench_probe.lua` deliberately probes a bare global `getVehiclesInArea`; annotated for luacheck/LuaLS.
6. `tests/check.sh` SC1087 (`$fn[[:space:]]`) — harmless in bash, braced for clarity; `cd` now `|| exit 1`.
7. `tools/gen_showcase_layout.py` ignores `--help` and regenerates its outputs (deterministic, so no
   diff) — worth an argparse guard.
8. **30 fps rule vs the capture backend:** `record.py` is a screenshot loop that measured ~14 fps at
   640×360. Defaults were changed to 30 fps and ≤960 px, but reaching a *real* 30 fps needs a proper
   screen-capture backend (e.g. PipeWire/ffmpeg) — verify the "fps actual" line before using a clip.
